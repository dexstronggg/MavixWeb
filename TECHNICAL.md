# MavixWeb — Техническое описание

Документ составлен в соответствии с ГОСТ 19.402-78 «Описание программы» и
ГОСТ 19.503-79 «Руководство системного программиста».

---

## 1. Аннотация

Документ содержит техническое описание программы «MavixWeb» —
веб-приложения системы дистанционного управления БПЛА «Mavix».
Веб-приложение реализует публичный лендинг проекта, личный кабинет
пользователя, страницы пользовательской и технической документации,
а также раздел скачивания клиентского программного обеспечения.
Документ предназначен для разработчиков, развёртывающих и
сопровождающих веб-приложение.

---

## 2. Общие сведения

### 2.1. Наименование

Полное наименование: «Веб-приложение Mavix» (MavixWeb).
Условное обозначение: `mavixweb`.
Версия: 0.1.0.

### 2.2. Программное обеспечение

| Компонент | Версия |
|---|---|
| Среда выполнения | Node.js ≥ 18.0 |
| Веб-сервер приложения | Express 4 |
| Управление переменными окружения | dotenv 16 |
| Язык клиентской части | JavaScript (ECMAScript 2020) |
| Язык разметки | HTML5 |
| Язык стилей | CSS3 (с CSS-переменными) |
| Менеджер пакетов | npm ≥ 9 |

Сторонние библиотеки в браузере не используются: вся клиентская
логика реализована на чистом JavaScript (vanilla JS). Шрифты
(Inter, JetBrains Mono) подгружаются с сервиса Google Fonts.

### 2.3. Назначение

Программа обеспечивает:

- размещение публичной информации о системе Mavix (описание
  назначения, архитектуры, видеодемонстрация);
- регистрацию пользователей и авторизацию по протоколу JWT через
  REST-API сервера MavixServer;
- восстановление и смену пароля через подтверждение по электронной
  почте;
- доступ к пользовательской и технической документации в формате
  HTML после входа в личный кабинет;
- скачивание клиентских пакетов программного обеспечения
  (MavixDesktop, MavixBoard) с использованием механизма сборки
  сервера, вшивающего идентификаторы пользователя и дрона в
  бортовой пакет.

## 3. Функциональное назначение

### 3.1. Класс решаемых задач

Веб-приложение представляет собой клиент к серверу MavixServer
и решает следующие классы задач:

- представление статической информации (HTML-страницы лендинга и
  документации);
- интерактивное взаимодействие пользователя с API сервера
  (запросы аутентификации, восстановления пароля, проверки
  доступности сервера);
- хранение пользовательской сессии в локальном хранилище браузера
  (`localStorage`) с автоматическим обновлением токена доступа.

### 3.2. Сведения о функциональных ограничениях

- Веб-приложение не выполняет управление дронами и не работает с
  видеопотоками: эти задачи решает MavixDesktop. Сайт
  предоставляет лишь точку доступа к учётной записи и пакетам ПО.
- Для работы личного кабинета и любой авторизованной операции
  необходим запущенный и доступный по сети экземпляр MavixServer.
- При недоступности сервера в течение 5 секунд при загрузке
  кабинета в верхней части страницы отображается информационный
  баннер; возможность входа и скачивания при этом сохраняется до
  фактической ошибки запроса.
- Веб-приложение не предоставляет интерфейса администрирования и
  не имеет средств управления другими пользователями.

### 4.2. Описание основных модулей

#### 4.2.1. Серверный модуль (`server.js`)

Серверная часть реализует следующие функции:

1. **Раздача статического содержимого.** Все файлы из каталога
   `public/` доступны по соответствующим URL (`express.static`).

2. **Сопоставление маршрутов и страниц.** Объект `PAGES` задаёт
   соответствие URL приложения и HTML-файлов. Это позволяет
   обращаться к страницам по понятным путям без расширения `.html`
   (например, `/dashboard/settings` → `settings.html`).

3. **Инъекция конфигурации.** По запросу `GET /config.js` сервер
   формирует и возвращает JavaScript-фрагмент вида
   `window.MAVIX_CONFIG = { apiBaseUrl: "..." };`. Адрес API
   читается из переменной окружения `API_BASE_URL` и не вшивается
   в клиентский код. Это позволяет менять адрес сервера без
   пересборки.

4. **Обработка несуществующих маршрутов.** При обращении к
   неизвестному URL возвращается страница `404.html` с кодом 404.

#### 4.2.2. Клиент REST-API (`api.js`)

Файл инкапсулирует все обращения к серверу MavixServer и
предоставляет глобальный объект `window.MavixAPI`. Базовый URL
формируется как `${MAVIX_CONFIG.apiBaseUrl}/api/v1`.

Основные функции объекта:

| Метод | Назначение |
|---|---|
| `register(email, password)` | Регистрация пользователя и автоматический вход |
| `login(email, password)` | Авторизация и сохранение токенов |
| `logout()` | Очистка локального хранилища |
| `passwordResetRequest(email)` | Запрос письма для смены пароля |
| `passwordResetConfirm(token, newPassword)` | Подтверждение нового пароля |
| `health()` | Проверка доступности сервера |
| `validateEmail(email)` | Клиентская валидация email |
| `validatePassword(pw)` | Клиентская валидация пароля |

Токены доступа и обновления хранятся в `localStorage` под ключами
`mavix_access` и `mavix_refresh`. При получении кода `401` на
авторизованном запросе клиент автоматически выполняет запрос
`POST /auth/refresh` с обновляющим токеном и повторяет исходный
запрос с новым токеном доступа.

Все запросы выполняются с тайм-аутом 10 секунд (`AbortController`).
При истечении таймаута или сетевой ошибке генерируется исключение
`ApiError` с пустым кодом статуса.

#### 4.2.3. Защита маршрутов (`auth-guard.js`)

Скрипт подключается на страницах личного кабинета. Если в
`localStorage` отсутствует токен доступа, выполняется немедленное
перенаправление на страницу входа `/login`.

#### 4.2.4. Общая логика кабинета (`cabinet.js`)

Подключается на всех страницах личного кабинета. Реализует:

1. **Заполнение пользовательского профиля.** Подставляет email,
   USER_ID и инициал пользователя в элементы с атрибутами
   `data-role="header-email"`, `avatar`, `email`, `user-id`,
   `hello-email`. Снимает CSS-класс `is-skeleton`, скрывавший
   плейсхолдеры до загрузки.

2. **Проверка доступности сервера.** При загрузке страницы
   выполняется запрос `GET /api/v1/health` с тайм-аутом 5 секунд.
   При его неудаче в верхней части страницы создаётся баннер с
   предупреждением о недоступности сервера. Баннер можно закрыть;
   повторный показ откладывается на 5 минут (хранится в
   `sessionStorage`).

#### 4.2.5. Индикатор силы пароля (`pw-strength.js`)

Подключается на страницах регистрации и установки нового пароля.
Автоматически находит все поля `input[type="password"]` с
атрибутом `data-strength`, вычисляет уровень сложности пароля
по совокупности признаков (длина, регистр, цифры, специальные
символы) и отображает цветовую полоску под полем. Уровни:
«Слабый», «Средний», «Надёжный».

#### 4.2.6. Логика отдельных страниц

Каждая страница приложения подключает собственный скрипт из
каталога `js/pages/`, реализующий специфическую логику:

- `login.js` — валидация формы, вход через `MavixAPI.login`,
  перенаправление на `/dashboard` при успехе;
- `register.js` — валидация формы, проверка совпадения паролей,
  регистрация и автоматический вход;
- `forgot-password.js` — запрос письма для сброса пароля;
- `reset-password.js` — установка нового пароля по токену из
  URL-параметра;
- `settings.js` — отправка запроса на смену пароля на email
  текущего пользователя.

## 5. Используемые технические средства

### 5.1. Минимальные требования к серверной части

- Процессор: совместимый с архитектурой x86_64 или ARM64.
- Оперативная память: не менее 256 МБ.
- Дисковое пространство: не менее 100 МБ для приложения и зависимостей.
- Операционная система: GNU/Linux (Ubuntu 22.04+, Debian 12+),
  macOS 12+ или Windows 10/11.
- Сетевой доступ: открытый TCP-порт (по умолчанию 3001) и
  доступ к серверу MavixServer.

### 5.2. Требования к клиентской части

Веб-приложение проверено на следующих браузерах:

- Mozilla Firefox 115+;
- Google Chrome / Chromium 110+;
- Microsoft Edge 110+;
- Safari 16+.

Используются возможности ECMAScript 2020 (`async/await`,
опциональная цепочка, `URLSearchParams`), CSS-переменные,
Intersection Observer, AbortController.

## 6. Установка и настройка

### 6.1. Получение исходного кода

```sh
git clone https://github.com/dexstronggg/MavixWeb.git
cd MavixWeb
```

### 6.2. Установка зависимостей

```sh
npm install
```

Команда устанавливает пакеты Express и dotenv, перечисленные в
`package.json`. Сторонних бинарных модулей не требуется.

### 6.3. Конфигурация

Создайте файл `.env` в корне проекта со следующим содержимым:

```env
# Порт, на котором будет слушать MavixWeb.
PORT=3001

# Базовый URL сервера MavixServer (без хвостового /).
# При локальной разработке — обычно http://localhost:8000.
API_BASE_URL=http://localhost:8000
```

При отсутствии файла `.env` используются значения по умолчанию:
`PORT=3001`, `API_BASE_URL=http://localhost:8000`.

### 6.4. Настройка CORS на сервере

В переменной окружения `CORS_ALLOW_ORIGINS` сервера MavixServer
должен присутствовать адрес, на котором развёрнут MavixWeb,
например:

```env
CORS_ALLOW_ORIGINS=http://localhost:3001
```

Без этой настройки браузер заблокирует кросс-доменные запросы к
API.

### 6.5. Запуск

```sh
npm start
```

В стандартном выводе появятся сообщения:

```
[mavix-web] listening on http://localhost:3001
[mavix-web] API_BASE_URL=http://localhost:8000 (браузер получает через /config.js)
```

После этого приложение доступно по адресу из первой строки.

## 7. Проверка работы

### 7.1. Доступность статических ресурсов

```sh
curl -I http://localhost:3001/
curl -I http://localhost:3001/css/base.css
curl -I http://localhost:3001/js/api.js
```

Все три запроса должны возвращать статус `200 OK`.

### 7.2. Инъекция конфигурации

```sh
curl http://localhost:3001/config.js
```

Ожидаемый ответ:

```
window.MAVIX_CONFIG = {"apiBaseUrl":"http://localhost:8000"};
```

### 7.3. Корректность маршрутов

Каждая страница должна быть доступна по «человеческому» URL без
расширения `.html`:

```sh
curl -I http://localhost:3001/login
curl -I http://localhost:3001/register
curl -I http://localhost:3001/dashboard
curl -I http://localhost:3001/dashboard/settings
curl -I http://localhost:3001/dashboard/docs/user
curl -I http://localhost:3001/dashboard/docs/technical
curl -I http://localhost:3001/dashboard/software
```

### 7.4. Несуществующие маршруты

```sh
curl -I http://localhost:3001/no-such-page
```

Ответ должен иметь статус `404 Not Found` и содержать HTML-страницу
ошибки.

### 7.5. Связь с API

При открытии страницы регистрации в браузерной консоли не должно
быть ошибок CORS или сетевых ошибок. Регистрация и вход должны
завершаться перенаправлением на `/dashboard`.

## 8. Сообщения системному программисту

| Сообщение | Причина | Действия |
|---|---|---|
| `EADDRINUSE: address already in use :::3001` | Порт уже занят другим процессом | Завершить процесс, занявший порт, или изменить `PORT` в `.env` |
| `Cannot find module 'express'` | Не установлены зависимости | Выполнить `npm install` |
| `ENOENT: no such file or directory, open './public/...'` | Повреждён или не клонирован каталог `public/` | Получить актуальную копию репозитория |
| «Сервер не отвечает. Проверьте, что MavixServer запущен на …» | Тайм-аут клиентского запроса (10 с) | Убедиться, что MavixServer запущен и доступен |
| «Не удалось подключиться к серверу. Проверьте сеть.» | Сетевая ошибка `fetch` на клиенте | Проверить сетевые настройки и DNS |
| «Email уже зарегистрирован.» (HTTP 409) | Регистрация существующего email | Войти под существующей учётной записью |
| «Проверьте корректность введённых данных.» (HTTP 422) | Невалидный ввод | Скорректировать форму |
| «Слишком много попыток. Попробуйте позже.» (HTTP 429) | Сработал rate limit MavixServer | Подождать и повторить |

## 9. Журналирование

Веб-сервер MavixWeb выводит в стандартный поток вывода:

- сообщение о запуске с указанием порта и адреса проксируемого API;
- стандартные предупреждения Node.js (при их возникновении).

Запросы по умолчанию не журналируются для уменьшения шума в
консоли разработчика. При необходимости логирования запросов
рекомендуется подключить пакет `morgan` либо реализовать
собственный middleware в `server.js`.

Клиентская часть никаких файлов журнала не создаёт. Сетевые
ошибки выводятся в виде сообщений в форме (`form-error`) и в
консоль браузера (`console.error`).
