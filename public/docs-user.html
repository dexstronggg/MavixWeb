Что такое Mavix

Mavix — система FPV-пилотирования дронов через интернет. Видеопоток с камеры дрона приходит к вам напрямую по технологии WebRTC, а команды управления с USB-джойстика уходят на полётный контроллер дрона по протоколу CRSF (для Betaflight/iNav) или MAVLink (для ArduPilot/PX4). Сервер отвечает только за авторизацию и за то, чтобы дрон и оператор нашли друг друга в сети — само видео и команды идут между ними напрямую.

Чтобы пользоваться системой, нужны три вещи: ваш аккаунт, прошивка MavixBoard на дроне (Raspberry Pi) и приложение MavixDesktop на вашем ПК.

Что вам понадобится

  • Raspberry Pi 4 или новее с Ubuntu Server 24.04 LTS или Raspberry Pi OS. Устанавливается на дрон рядом с полётным контроллером.
  • Полётный контроллер с одной из поддерживаемых прошивок: Betaflight, iNav (через CRSF по UART) или ArduPilot/PX4 (через MAVLink по USB).
  • Камера: USB-камера (тестируется через fswebcam) или CSI-камера через libcamera/rpicam. Поток кодируется в H.264 на стороне дрона.
  • ПК с Windows 10+ или Linux x64 — для приложения оператора.
  • USB-джойстик — Radiomaster Pocket (Mode 2 / EdgeTX) и аналоги. Поддерживаются также обычные геймпады.
  • Стабильный интернет и на дроне, и на ПК. Для дрона подойдёт Wi-Fi или LTE-модуль (Waveshare SIM7600 и аналоги).

Подготовка Raspberry Pi

Установщик install.sh ставит только программную часть — GStreamer, Python-зависимости и службу MavixBoard. Доступ к UART-порту, отключение служебной консоли и права на устройства установщик не настраивает: это нужно сделать один раз вручную до установки MavixBoard. Без этого дрон с Betaflight/iNav не получит управление по CRSF (FC будет показывать RXLOSS).

Если у вас ArduPilot или PX4 и связь идёт по USB (/dev/ttyACM*), настройка UART из этого раздела не нужна — переходите сразу к шагу установки MavixBoard. Раздел обязателен только для Betaflight/iNav (CRSF по UART) либо если ваш ArduPilot/PX4 подключён к FC не по USB, а по аппаратному UART.

1. Включите аппаратный UART (только Betaflight/iNav по CRSF)

Добавьте в /boot/firmware/config.txt: 

enable_uart=1
dtoverlay=disable-bt

dtoverlay=disable-bt обязателен — он отключает Bluetooth и переключает выводы GPIO14/15 с медленного mini-UART на полноценный PL011 (ttyAMA0), который держит 420 000 бод, нужные для CRSF.

2. Отключите служебную консоль на порту

По умолчанию Linux держит на ttyAMA0 вход в систему (serial console) — он мешает CRSF. Отключите его: 

sudo raspi-config
# Interface Options -> Serial Port:
#   Login shell over serial: No
#   Serial port hardware:    Yes

Либо вручную уберите console=serial0,115200 из /boot/firmware/cmdline.txt и отключите getty-службу: 

sudo systemctl disable --now serial-getty@ttyAMA0.service

3. Дайте права на serial-порты без sudo

Добавьте пользователя в группы dialout и tty: 

sudo usermod -aG dialout,tty $USER

Чтобы права на устройства держались стабильно после каждой загрузки, создайте udev-правило /etc/udev/rules.d/99-serial.rules: 

KERNEL=="ttyAMA[0-9]*", GROUP="dialout", MODE="0660"
KERNEL=="ttyUSB[0-9]*", GROUP="dialout", MODE="0660"
KERNEL=="ttyACM[0-9]*", GROUP="dialout", MODE="0660"

И примените его:

sudo udevadm control --reload-rules && sudo udevadm trigger

Служба MavixBoard запускается от root, поэтому работает с портом и без групп. Группы нужны для ручного запуска и отладки без sudo, а также для камеры (группа video).

4. Перезагрузите Raspberry Pi

Изменения в config.txt и cmdline.txt применяются только после перезагрузки: 

sudo reboot

После перезапуска порт /dev/ttyAMA0 готов к работе на 420 000 бод без дополнительных команд при каждом старте.

Первый полёт: от установки до взлёта

1. Зарегистрируйтесь и войдите

На сайте Mavix создайте аккаунт по email и паролю. После входа вам станет доступна страница «Скачать» — там лежат все программы.

2. Установите MavixDesktop на ПК

Скачайте приложение оператора для вашей операционной системы: .exe для Windows или .AppImage для Linux. При первом запуске войдите своим email и паролем. После авторизации откроется экран со списком дронов — пока он будет пустым.

3. Установите MavixBoard на дрон

Скачайте установщик MavixBoard (архив .tar.gz) — при сборке сервер встраивает в него токен регистрации вашего аккаунта, так что дрон сам привяжется к вам при первом запуске. Перенесите файл на Raspberry Pi и распакуйте: 

tar xzf mavixboard-XXXXXXXX.tar.gz
cd mavixboard-XXXXXXXX
sudo ./install.sh

Установщик создаст изолированный Python-venv в /opt/mavixboard/, поставит все зависимости из архива (интернет в этот момент не нужен) и положит ваш токен в /etc/mavixboard/preset.env.

Ручной запуск (для проверки, что всё работает): 

set -a; . /etc/mavixboard/preset.env; set +a
sudo /opt/mavixboard/.venv/bin/python -m mavixboard

Останавливается Ctrl+C. Если хотите, чтобы дрон стартовал автоматически при включении питания, включите systemd-юнит: 

sudo systemctl enable --now mavixboard
sudo journalctl -u mavixboard -f

После этого служба будет автоматически запускаться при каждой загрузке RPi.

Один архив — сколько угодно дронов. Идентификатор дрона в архив не зашивается: каждая Raspberry Pi генерирует его сама при первом запуске и получает от сервера собственные DRONE_ID и DRONE_TOKEN, которые дописываются в /etc/mavixboard/preset.env. Поэтому один и тот же скачанный .tar.gz можно поставить на любое число бортов — в личном кабинете они появятся как отдельные дроны, каждый под своим именем.

Обратная сторона: в архиве лежит токен регистрации вашего аккаунта. Кто получил архив, тот может зарегистрировать дрона на вас — не передавайте его посторонним.

Обновление MavixBoard

Когда выходит новая версия, достаточно скачать свежий установщик .tar.gz со страницы «Скачать» и повторно запустить install.sh. Переустановка идёт поверх старой версии: код обновляется, а идентичность дрона (DRONE_ID/DRONE_TOKEN) сохраняется — он не зарегистрируется как новый. 

tar xzf mavixboard-XXXXXXXX.tar.gz
cd mavixboard-XXXXXXXX
sudo ./install.sh
sudo systemctl restart mavixboard
Перезапуск службы обязателен: борт читает настройки и токены один раз при старте, поэтому после установки нужно перезапустить mavixboard, чтобы новый код заработал.

4. Настройте полётный контроллер

Betaflight / iNav (CRSF). Подключите три провода между RPi и FC: RPi TX (Pin 8) → FC UART RX, FC UART TX → RPi RX (Pin 10), и GND на GND. Соединение перекрёстное (TX идёт на RX), питание не нужно — оба устройства 3.3В.

ArduPilot / PX4 (MAVLink). Просто соедините FC с Raspberry Pi кабелем USB. Трансмиттер сам найдёт FC на /dev/ttyACM* — провода UART и настройка из шага 4 не нужны.

Конкретная настройка прошивки зависит от вашего FC — подробности в разделе «Поддерживаемые полётные контроллеры».

5. Дождитесь появления дрона в списке

Когда дрон подключится к серверу, он автоматически появится в окне MavixDesktop. Список обновляется автоматически.

6. Подключитесь и взлетайте

Кликните по карточке дрона. Откроется окно с видеопотоком и панелью настройки. На первом запуске рекомендуется выполнить калибровку камеры — приложение само переберёт поддерживаемые разрешения и FPS.

Поддерживаемые полётные контроллеры

Mavix работает с тремя семействами прошивок:

  • Betaflight — CRSF по UART на 420 000 бод
  • iNav — CRSF по UART (требует receiver_type = SERIAL и serialrx_halfduplex = OFF)
  • ArduPilot / PX4 — MAVLink по USB через /dev/ttyACM*

Betaflight (CRSF)

Подключите FC по USB, откройте Betaflight Configurator → вкладка CLI. Минимальный конфиг на примере UART4 (пады T4/R4): 

serial 3 64 115200 57600 0 115200
set serialrx_provider = CRSF
set serialrx_inverted = OFF
feature TELEMETRY
map TAER1234
aux 0 0 0 1800 2100 0 0
save

Здесь serial 3 64 … — UART4 в режиме Serial RX, aux 0 … — ARM на тумблере AUX1 (CH5, диапазон 1800–2100).

iNav (CRSF)

iNav, в отличие от Betaflight, требует явно указать receiver_type = SERIAL и serialrx_halfduplex = OFF — без этого FC не примет CRSF-кадры, даже если порт настроен верно. Полный конфиг через CLI (UART4): 

serial 3 64 115200 115200 0 115200
set receiver_type = SERIAL
set serialrx_provider = CRSF
set serialrx_inverted = OFF
set serialrx_halfduplex = OFF
set small_angle = 180
set min_check = 1000
feature TELEMETRY
map TAER
aux 0 0 0 1800 2100 0 0
aux 1 3 0 900 2100 0 0
calibrate acc
save
  • set min_check = 1000 — без него iNav считает, что газ не на нуле (CRSF в покое ≈ 989), и не армится (флаг THR).
  • set small_angle = 180 — снимает блокировку арма при наклоне дрона больше 25°.
  • aux 1 3 0 900 2100 — режим ANGLE всегда активен. Без стабилизации дрон летит в ACRO — это опасно при управлении через интернет.
  • Перед calibrate acc положите FC ровно на стол. Скорость CRSF в iNav жёстко задана как 420 000 бод — цифры baudrate в команде serial игнорируются.

ArduPilot / PX4 (MAVLink)

Настройка трансмиттера не требуется — он автоматически определяет MAVLink FC по USB (/dev/ttyACM*) и пробрасывает поток в QGroundControl через UDP 14550. Что может понадобиться на стороне FC (через QGroundControl → Parameters):

  • BRD_SAFETY_DEFLT = Disabled — если на плате (например, Pixracer) нет физической кнопки безопасности или вы её не используете.
  • ARMING_CHECK = 0 — отключает все предполётные проверки. Только для наземных тестов без пропеллеров!
  • RC_PROTOCOLS — протокол приёмника: 1 для PPM, 256 для iBUS (например, FlySky FS-iA6B).
ArduPilot 4.0+ работает только на ChibiOS (поддержка NuttX убрана). PX4 по-прежнему использует NuttX. На современных платах (Pixracer, Matek H743, Skystars H743) для ArduPilot выбирайте ChibiOS.

Работа в приложении оператора

Главный экран приложения — список ваших дронов. Каждая карточка показывает имя дрона и индикатор статуса:

  • Зелёный — дрон подключён и готов к управлению.
  • Жёлтый — идёт подключение.
  • Серый — дрон не на связи (выключен или вне сети).

В шапке кабинета доступна страница настройки джойстиков. В окне управления дроном внизу справа отображается текущий пинг.

Подключение и калибровка джойстика

Подключите джойстик к USB-порту ПК — он сразу появится в списке. Для каждого устройства доступны действия:

  • Калибровка — 11-шаговый мастер: центр, максимум/минимум по каждой оси (тяга, рыскание, тангаж, крен), кнопка ARM, затем кнопка сброса груза (шаг можно пропустить).
  • Загрузить из файла — восстановите ранее сохранённую калибровку.
  • Сохранить в файл — выгрузите свою калибровку для другого ПК.

Стандартный маппинг для Radiomaster Pocket (Mode 2 / EdgeTX):

СтикКаналФункция
Правый XCH2Крен (Roll)
Правый YCH3Тангаж (Pitch)
Левый YCH1Тяга (Throttle)
Левый XCH4Рыскание (Yaw)
ТумблерCH5ARM / DISARM
Кнопка сбросаCH6Сброс груза
Остальные кнопки, оси, крестовинаCH7 и далееСвободные тумблеры

Тумблеры на Pocket экспортируются как оси, а не кнопки — приложение определяет тип автоматически.

Всё, что не занято стиками и ARM, передаётся на полётник автоматически. Какой орган управления попал на какой канал — показано на последнем шаге калибровки. Кнопки работают как переключатели: нажали — канал ушёл вверх и остался там, нажали снова — вернулся.

Чтобы канал что-то делал, назначьте ему режим в конфигураторе полётника (Betaflight или iNav, вкладка Modes). Нумерация AUX начинается с нуля: CH7 — это AUX3, то есть aux 2 <режим> 2 1800 2100 0 0.

В полётном режиме над надписью ARM/DISARM показывается состояние груза — ГРУЗ НА БОРТУ или ГРУЗ СБРОШЕН. Надпись появляется только если кнопка сброса назначена при калибровке.

После сброса надпись остаётся «ГРУЗ СБРОШЕН» до конца полёта, даже если вернуть тумблер в исходное положение — груза на борту уже нет. Сам тумблер возвращать можно и нужно: так замок закрывается.

Сброс защищён так же, как ARM: пока программа не увидит тумблер в положении «не сброшено», груз считается на борту. Взлететь с тумблером, забытым во включённом положении, и сразу раскрыть замок нельзя — сначала верните тумблер в исходное положение.

Только Betaflight и iNav. Тумблеры, кнопки и сброс груза передаются исключительно по протоколу CRSF, поэтому работают только с прошивками Betaflight и iNav.

Для ArduPilot и PX4 (подключение по MAVLink) передаются только стики, ARM и команды режимов. Отдельных каналов под тумблеры нет, сброс груза на этих прошивках не работает — надпись о состоянии груза в полётном режиме не появится.

Управление видеопотоком

В окне управления дроном:

  • Переключайте активную камеру стрелками ← → если их несколько.
  • Меняйте разрешение, FPS и битрейт. Битрейт применяется на лету, разрешение и FPS требуют короткой перезагрузки потока.
  • При переключении камер неактивная камера автоматически снижает битрейт до 200 кбит/с — канал не перегружается, поток не прерывается.
  • Запускайте принудительную калибровку камеры через кнопку «Калибровка камер». Во время неё дрон перебирает все доступные режимы — это может занять продолжительное время.

Порядок ARM и безопасность

Перед каждым полётом проверьте порядок включения:

  1. Отключите USB от полётного контроллера.
  2. Подключите батарею.
  3. Подождите 5 секунд — FC завершит инициализацию.
  4. Стик газа полностью вниз.
  5. Щёлкните тумблер ARM на джойстике.
Снимите пропеллеры перед первым тестом — особенно если вы только что прошили FC или поменяли калибровку.

Если что-то пошло не так

Дрон не появляется в списке

  • Проверьте, что служба запущена: systemctl status mavixboard.
  • Убедитесь, что у дрона есть выход в интернет (Wi-Fi или LTE).
  • Проверьте логи на дроне: journalctl -u mavixboard -f.

FC не армируется

В CLI любого FC введите status — строка Arming disabled flags покажет причину. Самые частые:

  • RXLOSS — нет RC-сигнала. Проверьте провода RPi ↔ FC, dtoverlay=disable-bt в /boot/firmware/config.txt, и что serial console отключена.
  • THROTTLE / THR — газ не на нуле. Стик газа полностью вниз, для iNav: set min_check = 1000.
  • ANGLE / ACC — дрон не ровно. Для iNav: set small_angle = 180 и calibrate acc.
  • MSP (Betaflight) — отключён USB, питайте от батареи.

Видео фризит или прерывается

  • Снизьте битрейт и FPS в настройках камеры.
  • Проверьте сигнал Wi-Fi или уровень LTE на дроне (mmcli -m 0).
  • Если оба устройства за NAT с симметричной фильтрацией, потребуется TURN-сервер.

Не работает джойстик

  • Проверьте, что устройство видно в системе (на Linux — jstest /dev/input/js0).
  • Сделайте новую калибровку — старая могла быть выполнена для другого устройства.

WebRTC не подключается

  • Проверьте, что у дрона стабильное интернет-соединение.
  • Если используется LTE — установите приоритет: sudo nmcli connection modify lte ipv4.route-metric 50.
  • В сложных сетях с симметричным NAT нужен TURN-сервер.

Забыли пароль

На странице входа нажмите «Забыли пароль?» — сервер отправит вам письмо со ссылкой для сброса. Ссылка действительна один час.

Где лежат логи

Если нужно приложить логи к обращению в поддержку — вот где их искать. Файлы ротируются автоматически, старые версии получают суффикс .1, .2 и так далее.

Приложение оператора (MavixDesktop)

  • Linux и macOS: ~/.config/mavixdesktop/logs/mavixdesktop_ГГГГ-ММ-ДД.log
  • Windows: %APPDATA%\mavixdesktop\logs\mavixdesktop_ГГГГ-ММ-ДД.log
    то есть C:\Users\<имя>\AppData\Roaming\mavixdesktop\logs\. Каталог AppData скрытый — путь удобнее вставить прямо в адресную строку проводника.
  • Рядом, в том же каталоге, лежит stats_ГГГГ-ММ-ДД.jsonl — посекундная статистика канала (битрейт, потери, задержка, замирания). Именно этот файл полезнее всего при жалобах на качество видео.

Ротация: до 10 МБ на файл, хранится 5 предыдущих.

Прошивка дрона (MavixBoard)

  • Файл на самом дроне: /var/log/mavixboard/mavixboard_ГГГГ-ММ-ДД.log
  • То же самое в системном журнале — удобно смотреть вживую: journalctl -u mavixboard -f

Ротация: до 2 МБ на файл, хранится 3 предыдущих. Каталог задаётся переменной MAVIXBOARD_LOG_DIR в юните службы; если запускать MavixBoard вручную из распакованных исходников, логи вместо этого лягут в подкаталог _log рядом с ними.

Скопировать логи дрона на компьютер можно так: 

scp pi@<адрес-дрона>:/var/log/mavixboard/mavixboard_*.log .
Полная техническая спецификация (архитектура WebRTC, формат CRSF-фреймов, схемы подключения) доступна в разделе «Техническая документация».
