Общая архитектура

Mavix состоит из трёх независимых модулей: прошивки Board на дроне, десктоп-клиента Desktop на ПК оператора и Server — сервиса сигнализации и авторизации.

Server занимается только тремя задачами: аутентификация пользователей и дронов, регистрация дронов в системе и обмен SDP/ICE-кадрами между Board и Desktop при установлении WebRTC-соединения. После handshake обе стороны устанавливают прямой peer-to-peer-канал, и медиа с данными управления идёт через него, минуя сервер.

Такой подход даёт два важных эффекта: низкую задержку (видео не делает лишний хоп через сервер) и линейную масштабируемость (нагрузка на сервер не зависит от количества активных полётов).

Компоненты системы

MavixBoard — прошивка дрона

Запускается на Raspberry Pi под Ubuntu Server 24.04 или Raspberry Pi OS. Реализована на Python 3.11+ с использованием asyncio, GStreamer для захвата и кодирования видео, aiortc для WebRTC, pymavlink для общения с полётным контроллером.

Координатор сессии связывает SignalClient (WebSocket к серверу), WebRTCManager (peer-сессии с PC) и FCService (полётный контроллер). Использует exponential backoff при переподключении, watcher отслеживает USB-камеры и hot-plug полётного контроллера.

MavixDesktop — приложение оператора

Кроссплатформенный GUI на PySide6. WebRTC peer организован через aiortc, видеообработка — через PyAV и OpenCV. Джойстики опрашиваются через pygame. Токены доступа хранятся в системном keyring (Keychain на macOS, Secret Service на Linux, Credential Manager на Windows) с фолбэком в JSON-файл.

MavixServer — сервер сигнализации

FastAPI на Uvicorn, Python 3.11+. PostgreSQL (через SQLAlchemy 2.0 async и asyncpg) хранит пользователей и дронов. Alembic управляет миграциями. Авторизация — JWT (HS256) через PyJWT, пароли — bcrypt. Письма (welcome, восстановление пароля) уходят через fastapi-mail по SMTP. Rate limiting — slowapi.

WebSocket-эндпоинты /ws/drone и /ws/gcs обслуживают пары «дрон ↔ оператор»: ConnectionRegistry хранит активные соединения, SignalRelay пересылает SDP и ICE-кандидатов. HeartbeatMonitor закрывает зависшие сессии, AuthExpiryMonitor предупреждает клиента за минуту до истечения JWT.

Протоколы и форматы

WebRTC

Сигнализация по WebSocket: дрон отправляет SDP-offer, оператор отвечает SDP-answer, обе стороны обмениваются ICE-кандидатами. STUN/TURN-серверы указываются в конфиге сервера и раздаются клиентам через эндпоинт /api/v1/ice-servers.

После установления peer-соединения создаются три data-канала:

  • packet-channel — пакеты CRSF от оператора к дрону.
  • ping-channel — измерение задержки в обе стороны.
  • config-channel — изменение параметров камеры на лету, уведомления об ошибках pipeline, обновление списка камер.

MAVLink

Внутреннее общение Board с полётным контроллером. Поддерживается стандартный набор сообщений (heartbeat, attitude, GPS, command_long).

CRSF

Команды каналов управления (стики джойстика) от оператора уходят в формате CRSF и через UART-приёмник попадают на полётный контроллер.

API сервера

REST-эндпоинты с префиксом /api/v1. Все запросы и ответы — JSON. Авторизация — заголовок Authorization: Bearer <JWT>.

Аутентификация

  • POST /api/v1/auth/register — регистрация по email + паролю.
  • POST /api/v1/auth/login — вход, возвращает access и refresh-токены.
  • POST /api/v1/auth/refresh — обновление access-токена по refresh.
  • POST /api/v1/auth/password-reset/request — отправка письма со ссылкой сброса.
  • POST /api/v1/auth/password-reset/confirm — установка нового пароля по токену из письма.

Дроны и сборки

  • POST /api/v1/drones/register — регистрация дрона за пользователем.
  • GET /api/v1/builds/board.deb — .deb для дрона с вшитыми токенами (требует ?drone_id=…).
  • GET /api/v1/builds/desktop.deb — generic-пакет десктоп-клиента.

Системное

  • GET /api/v1/health — проверка состояния сервера.
  • GET /api/v1/ice-servers — список STUN/TURN для WebRTC.

Полная Swagger-схема доступна по адресу /docs на запущенном сервере.

Модель безопасности

  • Пароли хранятся как bcrypt-хеши с автоматически сгенерированной солью. Длина пароля ограничена 72 байтами (явное ограничение из-за специфики bcrypt).
  • Access-токен живёт 15 минут, refresh-токен — 30 дней. Refresh не ротируется при использовании: на сервер можно отправить один и тот же refresh повторно, пока он не истёк или пользователь не удалён.
  • Reset-токен для восстановления пароля живёт один час и подписан тем же секретом сервера. Тип токена различается claim type: access / refresh / reset.
  • Дрон аутентифицируется отдельным 64-символьным drone_token при подключении к /ws/drone. Этот токен встраивается в .deb-пакет при сборке и не передаётся пользователю напрямую.
  • Anti-enumeration: запрос восстановления пароля возвращает одинаковый ответ независимо от того, существует ли email в базе. Ответы на неверный пароль и несуществующий email идентичны (оба 401).
  • Rate limiting на уровне IP через slowapi. Конфигурация — переменная RPM в окружении сервера.

Сборка и распространение

Все три модуля используют pyproject.toml с hatchling в качестве build-backend. Board и Desktop собираются в нативные пакеты:

  • Board — .deb для Raspberry Pi. Сборка происходит на сервере на лету: при запросе /api/v1/builds/board.deb сервер копирует шаблон дерева пакета, пишет файл /etc/mavixboard/preset.env с переменными USER_ID, DRONE_TOKEN и SIGNAL_SERVER_IP, и вызывает dpkg-deb --build. Результат кэшируется по SHA256 от пакета и идентификатора дрона.
  • Desktop — generic .deb / Windows installer / macOS app, без вшитых учётных данных (Desktop логинится email + паролем).
  • Server распространяется в Docker. Поставляется с Dockerfile и docker-compose.yaml для быстрого поднятия с PostgreSQL.
Все три репозитория содержат собственные документы по ГОСТ 19.402-78 (техническое описание) и ГОСТ 19.505-79 (руководство оператора).
